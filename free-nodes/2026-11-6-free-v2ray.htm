定时脚本：概念与魔力

什么是定时脚本？

简单来说，定时脚本就是在预设的时间点或时间间隔内，自动执行的 JavaScript 代码片段。它就像是一个不知疲倦的机器人，严格按照你设定的日程表工作。想象一下这些场景：

  • 每天早晨 8 点，自动检测你的服务器是否在线，并在异常时发送通知。
  • 每 30 分钟，自动刷新一次某个 API 的认证令牌，确保连接永不中断。
  • 每周日凌晨，自动清理一次本地缓存日志，保持设备轻盈。

这些听起来繁琐且易忘的任务，在定时脚本面前都变得轻而易举。它不仅是“自动化”，更是一种“智能化”——让网络环境主动适应你的需求，而非被动等待你的指令。

定时脚本的核心价值

定时脚本的魔力在于三点：精准性、连续性、可编程性。精准性指它能在毫秒级的时间精度下执行任务；连续性意味着它不会因你的离开而停止工作，7×24 小时默默守护；可编程性则赋予你无限的创造空间，从简单的 HTTP 请求到复杂的逻辑判断，一切皆可代码化。这三者结合，让 Quantumult X 从一个被动代理工具，进化为一个主动的网络服务引擎。

第一步：进入定时器设置

打开 Quantumult X 应用，点击底部导航栏中的“设置”图标（通常是齿轮形状）。在设置界面中，向下滑动找到“脚本”一栏，点击进入后选择“定时器”。这里就是你管理所有定时任务的大本营。

第二步：新建任务

在定时器页面，点击右上角的“+”号，即可创建一个新的定时任务。此时，你会看到一个空白模板，需要填写以下关键信息：

  • 任务名称：给你的脚本起一个清晰易记的名字，比如“API健康检查”。
  • 执行间隔：选择执行频率。Quantumult X 提供了灵活的时间选项，从分钟级到天级均可自定义。你可以通过“分”“时”“日”的组合来设定精确的周期。
  • 脚本内容：这是核心区域。你需要在这里粘贴或编写 JavaScript 代码。

第三步：编写你的脚本逻辑

进阶技巧：让脚本更智能、更可靠

调试的艺术

编写脚本难免遇到 Bug，Quantumult X 提供了便捷的调试手段。在脚本中合理使用 console.log，然后通过主界面底部的“日志”面板查看输出。这里会显示所有脚本的运行日志，包括错误堆栈和自定义打印信息。对于复杂问题，你还可以临时在脚本中加入 $done() 提前终止执行，逐步定位问题。

善用环境变量与内置方法

Quantumult X 为脚本提供了丰富的内置对象和方法。例如：

  • $environment：获取当前网络环境信息（如 Wi-Fi/蜂窝数据）。
  • $prefs：读写持久化存储，用于跨任务保存状态。
  • $notification.post：发送系统通知，支持标题、正文和可选的声音。
  • $task.fetch：更底层的高性能请求方法，适合大量并发请求。

掌握这些 API，能让你的脚本从“能用”升级为“好用”。比如，你可以用 $prefs 记录上次检查的时间，避免重复报警；或者用 $task.fetch 并发检测多个节点，大幅提升效率。

周期设置的策略

执行周期的设置并非越短越好。过短的周期可能导致资源浪费，甚至触发 API 限流；过长的周期则可能错过关键时间点。建议根据任务性质灵活调整：

  • 关键监控（如服务器存活）：每 5-10 分钟一次。
  • 数据同步（如订阅更新）：每 6-12 小时一次。
  • 缓存清理（如日志删除）：每周一次。

同时，注意避开高峰期（如整点），以免与大量任务冲突。

常见问题与解决思路

Q1：脚本运行报错，如何排查？

首先查看日志中的错误信息，确定是语法错误还是运行时异常。如果是网络请求失败，检查 URL 是否可访问、是否需要携带认证头。如果是逻辑错误，尝试简化代码，逐步增加功能。

Q2：定时任务不执行，可能是什么原因？

检查任务是否处于启用状态；确认执行间隔设置正确；查看日志是否有“任务已跳过”的提示。另外，某些系统版本下，后台刷新权限可能受限，需在系统设置中允许 Quantumult X 的后台活动。

Q3：多个定时脚本之间如何协调？

Quantumult X 支持同时运行多个定时任务，它们之间互相独立。如果你需要任务之间传递数据，可以使用 $prefs 进行全局读写。但注意避免循环依赖，否则可能导致死锁。

Q4：有没有现成的优质脚本可以参考？

当然有。GitHub 上有大量开源的 Quantumult X 脚本仓库，涵盖代理节点检测、机场流量监控、签到任务等。建议先从简单脚本入手，阅读他人代码，理解其逻辑结构，再逐步改造为自己所用。这远比从零开始编写要高效得多。

FAQ

SSR 的混淆插件如何提高抗封锁能力？
通过混淆插件可以模拟正常 HTTPS 或 HTTP 流量，隐藏真实通信特征。合理选择混淆方式，可有效避免 DPI 检测，提高节点可用性和连接稳定性，保证长期科学上网。
Nekobox 如何分流多协议流量？
Nekobox 可以同时管理 Shadowsocks、VMess、Trojan 等多协议节点，通过策略组将不同流量分配到指定节点，实现精准分流，提高网络效率和管理便利性。
WinXray PAC 模式如何提高访问速度和便利性？
PAC 模式根据规则动态判断流量是否走代理，无需手动切换节点。适合国内外混合访问场景，提高网页和视频访问速度与稳定性，减少操作错误导致的访问失败。
Hiddify Next 如何设置用户带宽限制？
管理员可为每个用户设置上传和下载带宽上限。超出限制可自动降速或阻止访问，保证服务器资源合理分配，避免单用户占用过多带宽，提高整体公平性和使用效率。
VLESS 在高封锁环境下的优势是什么？
VLESS 去掉了内置加密，依赖 TLS 层安全，减少被 DPI 检测的特征。结合 XTLS 或 Reality 模式，可以更好地隐藏流量，提高在高封锁网络中的稳定性与隐蔽性。
WinXray 的内核能否替换？
可以。WinXray 的内核文件独立存在于程序目录中，用户可替换为最新的 v2ray-core 或 xray-core 文件以获取更好的性能与协议支持，但需保持版本兼容。
Shadowrocket 的节点测速如何优化策略组选择？
Shadowrocket 会测量节点延迟和丢包率，将低延迟节点优先使用。结合策略组和规则文件，可保证网页、视频和游戏流量走最佳节点，提高访问速度和连接稳定性。
V2Ray 中的 alterId 是什么，现在还有必要配置吗？
alterId 曾用于 VMess 的用户混淆机制以防止重放攻击，但在 V2Ray 新版本与 VLess 出现后，alterId 已不再推荐使用。现代配置多使用 UUID 或直接迁移至 VLess/XTLS 以获得更好性能与安全性。
WinXray 支持测速功能吗？
支持。WinXray 提供节点延迟测速功能，可检测每个节点的响应时间与可用性。测速结果能帮助用户选择最快线路，也能排除无效或不稳定的节点，提高整体网络体验。
PassWall2 在路由器上使用 TUN 模式会有什么影响？
启用 TUN 模式会拦截并转发路由器上全部或选定流量，这会增加路由器 CPU 与内存负担，可能影响路由器其他服务表现。建议在性能足够的设备上启用，或仅对特定设备/端口进行分流。
